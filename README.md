📌 Overview

Payment System — это завершённая микросервисная платёжная система, реализующая полный цикл аутентификации пользователей, управления счетами и обработки денежных транзакций.
Проект спроектирован с упором на корректность финансовых операций, идемпотентность запросов, асинхронную интеграцию и устойчивость к высоким нагрузкам.

Система построена как набор независимых сервисов, взаимодействующих через REST и Kafka, и полностью контейнеризирована с помощью Docker.

🔹 Архитектура и ключевая логика

Система состоит из нескольких сервисов, каждый из которых имеет собственную зону ответственности.

Auth Service

Отвечает за регистрацию пользователей, аутентификацию и выдачу JWT-токенов.
JWT используется всеми остальными сервисами как единый механизм авторизации.

Payment Service

Реализует основную бизнес-логику системы:

создание и обработку транзакций;

публикацию событий в Kafka через outbox-паттерн.

🔹 Обработка транзакций

Создание транзакции реализовано как атомарная бизнес-операция с чётким разделением ответственности.

🔹 Идемпотентность

Все операции создания транзакций требуют уникальный idempotencyKey.
Если запрос с таким ключом уже был обработан, повторная операция не выполняется, а клиент получает корректный ответ без изменения состояния системы.

Это позволяет безопасно обрабатывать повторы запросов, таймауты и повторные отправки со стороны клиента.

🔹 Как запустить проект
Запуск через Docker Compose
docker-compose up --build

docker-compose -f docker-compose.yml --compatibility up --scale auth-service=3 --scale payment-service=3 --build

docker-compose -f docker-compose.prod.yml --compatibility up --scale auth-service=3 --scale payment-service=3 --build


PostgreSQL, Kafka и Redis запускаются сразу, остальные сервисы нужно запускать вручную через docker desktop.
Базы данных и таблицы создаются автоматически при старте контейнеров.

🔹 Зачем этот проект

Проект демонстрирует практические навыки:

проектирования микросервисной архитектуры;

реализации финансовых транзакций;

обеспечения идемпотентности операций;

асинхронного взаимодействия через Kafka;

работы с Docker и масштабированием сервисов;

построения отказоустойчивых backend-систем.

Проект может использоваться как учебный пример или база для дальнейшего развития платёжных решений.
